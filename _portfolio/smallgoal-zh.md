我想知道每个月的钱都花到哪儿去了，又不想把银行数据交给又一个 App。SmallGoal 就是为这个写的，大概一个月前开始做。它跑在我自己的笔记本上：银行卡和信用卡的交易进来，清理、分类，变成每月一份收支报告，电脑和手机上都能看。

## 能干什么

<figure class="figure-wide">
  <img src="/assets/images/portfolio/smallgoal-phones.jpg" alt="三张手机截图：月度总览，待确认队列在问一笔转账的用途，交易列表">
</figure>

交易有两种进来的方式。一种是上传网银里下载的 CSV，Chase、Amex、Discover、Capital One、Citi、Bank of America、Wells Fargo 都能直接认出来，别的银行按表头自动识别。另一种是通过 Plaid 授权一次，之后自动同步：开机先补上关机期间的交易，运行中每三小时再拉一次。

每笔交易会被分进两级分类里，先按规则，规则没命中就用银行自带的分类兜底。

它专门盯着那些会让自己记的账悄悄出错的地方。用支票账户还信用卡，这笔钱会在两个账户里各出现一次；SmallGoal 会把两边配对，都不算进支出。同一个文件导两遍不会重复，同一天买了两杯同价的咖啡也还是两笔。

拿不准的时候，它会问。Zelle、Venmo 这类个人转账，分不了类的，大额支出，可能重复的，找不到另一边的转账，都会进「待确认」。回答一次，勾上「以后同类都这样处理」，这个回答就变成一条规则。

月度总览里有支出、收入、结余和储蓄率，和上个月的对比，分类占比，和上月同期对比的累计支出曲线，近六个月的趋势，花钱最多的商户，以及按账户的明细。手机上是一个可以加到主屏幕的网页应用，在家用 Wi-Fi 加访问令牌连，出门在外通过 Tailscale 连。

截图用的是应用自带的示例数据，不是我的真实账户。

## 架构

<figure class="figure-wide">
  <img src="/assets/images/portfolio/smallgoal-architecture-zh.svg" alt="架构：银行 CSV 和 Plaid 同步进入笔记本上的六步处理流程，写进 SQLite；FastAPI 把数据提供给在电脑浏览器或 iPhone 上打开的网页界面；旁边是下一阶段的大模型路由">
</figure>

所有东西都跑在一台 Windows 笔记本上。FastAPI 服务既提供 REST 接口，也直接提供网页界面。数据就是一个 SQLite 文件，每天自动备份一份；数据库结构的改动走 Alembic 迁移，升级不会丢数据。

不管从哪儿来的交易，都走同样的六步。先把原始那一行原封不动存下来，以后随时可以重新处理。金额一律存成整数「分」，避免小数的舍入误差。去重时有银行交易 ID 就用 ID，没有就看账户、日期、金额和描述。然后按规则分类，跨账户配对转账，拿不准的进待确认。

数据源是插件。接一家新银行，只要写一个类，告诉它怎么认出这家的文件、怎么读；去重、分类、配对、报表都直接复用。支付宝、微信支付和国内银行流水的插件已经把接口留好了，等回国再补上。

代码里守着几条规矩。我手动改过的交易，任何自动流程都不会覆盖。银行密码不经过这个应用：登录在 Plaid 托管的页面上完成，应用只拿到一个只读令牌，而且存在数据库之外。后端运行时只有六个依赖，前端只有 React 和 React DOM 两个，图表全是手写的 SVG。测试里还有一个假的 Plaid 服务器，不连真银行也能测同步。

## 接下来要做的

<figure class="figure-wide">
  <img src="/assets/images/portfolio/smallgoal-roadmap-zh.svg" alt="计划中的功能：收入按规则分进储蓄、旅游、成长、日常开销几个虚拟账户；只读的 Agent 读账本和各账户，提出新规则和分配调整，我确认后才生效">
</figure>

**虚拟账户。** 现在 SmallGoal 能告诉我钱花到哪儿去了。下一步是在花之前就决定钱该去哪儿。每笔收入进来，按我定的规则，按比例或者固定金额，自动分进几个用途不同的虚拟账户：储蓄、旅游、成长、日常开销。每个账户有自己的余额。真实的银行账户之间不会有钱挪动，这是叠在它们上面的一层账。

**接入 Agent 做财务分析。** 大模型这一层代码里已经有了：本地模型（Ollama、LM Studio）和云端 API（Claude、DeepSeek、通义）走同一个接口，一个出错就自动换下一个，可以设成只用本地，发往云端之前会先去掉卡号、账号和人名。在这上面，Agent 会写每月的总结，回答关于我自己花销的问题，指出不寻常的扣款，提议新规则。它只读不写。它提出的任何改动，都要和手动修改走同样的校验，并且等我确认。

再往后：解析银行的交易提醒邮件做到接近实时，推送通知，把手机版打包成 iPhone App，以及接入国内的支付数据源。
